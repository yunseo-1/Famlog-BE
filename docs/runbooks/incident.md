## 1. 알아차리기

- Alertmanager 알림 (`infra/prometheus/alerts.yml`): **RefreshTokenReuse**(탈취 의심), LoginFailureSpike, Http5xxSpike, AiBudgetReached, DeadLetters, WorkerDown
- 관리자 도구: 신고(특히 아동 안전·개인정보), 운영 배너(AI 비용·DLQ)
- 외부 제보: 이메일, 스토어 리뷰
- **인지 시각을 바로 적는다** (통지 기한의 기준).

## 2. 심각도

| 단계 | 예 | 목표 |
|---|---|---|
| 1 (긴급) | DB·백업·S3 유출, 키 유출(JWT 서명 키, DB·S3·Anthropic 키), 다른 가족 데이터가 보임 | 즉시 차단, 72시간 안 통지·신고 판단 |
| 2 (높음) | 특정 계정 탈취, 관리자 토큰 노출, 로그에 개인정보 기록 | 당일 차단 |
| 3 (보통) | 서비스 장애, 비용 이상, 오탐 신고 | 업무 시간 안 |

## 3. 차단 (먼저 막고, 나중에 분석)

| 상황 | 조치 |
|---|---|
| 계정 탈취 | 관리자 도구 `POST /admin/api/users/{userId}/sessions/revoke` (X-Admin-Token): 모든 기기 즉시 로그아웃(Access 토큰 바로 401, Refresh 거절, WebSocket 끊김), 감사 로그 `ADMIN_SESSIONS_REVOKED`. 사용자는 다시 로그인할 수 있다 |
| JWT 서명 키 유출 | `infra/scripts/gen-jwt-key.sh --force`로 새 키 → 이전 키를 검증 목록에서 뺀다 → 서버 재시작 (모든 토큰 무효, 전원 재로그인) |
| DB·Redis·S3·Anthropic·카카오·FCM 키 유출 | 해당 콘솔에서 키 교체 → `infra/.env` 갱신 → 재시작. 교체 전까지 외부 접근 차단(보안 그룹) |
| 관리자 토큰 노출 | `FAMLOG_ADMIN_TOKEN` 교체 후 재시작. `audit_logs`의 ADMIN_* 기록 확인 |
| AI 분석 이상(인젝션·과금) | 관리자 도구 기능 플래그 `ai.analysis` 끄기 (앱에 "잠시 멈춤" 안내) |
| 기능 결함으로 다른 가족 데이터 노출 | 해당 기능 플래그 끄기 또는 최소 지원 버전 올려 426, 핫픽스 |
| 서버 침해 의심 | 네트워크 격리, 디스크 스냅샷 보존(증거) 후 새 서버로 재배포, 모든 키 교체 |

- 세션 폐기 예: `curl -X POST -H "X-Admin-Token: $AT" https://<도메인>/admin/api/users/<userId>/sessions/revoke` (토큰은 화면·기록에 남기지 않는다)
- 증거 보존: 서버 로그(traceId), `audit_logs`, 백업 파일을 지우지 않는다. 보존 기간이 지나 지워지기 전에 따로 복사한다.

## 4. 영향 범위 산정

- 누가: 영향받은 사용자·그룹 id 목록 (로그 traceId, `audit_logs`, 접근 경로)
- 무엇이: 항목(닉네임, 메시지, 사진, 위치, 출생연도월 등)과 건수
- 언제부터 언제까지, 어떻게(원인), 지금도 진행 중인지
- 로그에는 본문·토큰·좌표가 없으므로(SEC-T9), 필요한 경우 DB에서 대상 id 기준으로만 확인한다

## 5. 통지·신고 (법률 검토 필요)

- **정보주체 통지**: 유출을 안 때부터 **72시간 안에**. 유출 항목·시점·경위, 피해를 줄이는 방법(비밀번호가 없으므로 소셜 계정 점검·재로그인 안내 등), 대응 조치, 피해 신고·상담 창구.
  - 방법: 앱 공지(관리자 도구 공지 + 푸시), 이메일은 받지 않으므로 앱·웹 공지가 기본
- **신고**: 1천 명 이상, 민감정보·고유식별정보, 외부 불법 접근 등 법정 기준에 해당하면 72시간 안에 개인정보보호위원회·KISA 신고
- 위치정보 유출이면 위치정보법 절차도 확인
- 확인되지 않은 사실은 "확인 중"으로 먼저 알리고 추가 통지한다

## 6. 복구·재발 방지

- 데이터가 손상됐으면 `backup.md` 4·5절 (복구 뒤 삭제 요청 다시 적용)
- 원인 수정 → 테스트 추가(보안 테스트 체크리스트 SEC-T1~T10에 사례 추가) → 배포
- 사후 검토(일주일 안): 타임라인, 원인, 잘한 점·아쉬운 점, 재발 방지 작업과 기한
